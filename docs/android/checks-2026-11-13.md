# Checks for Alex — 2026-11-13

> Every « check for Alex » list from the night of 2026-11-12/13 (XBA-101 to XBA-137), in one order: the Mac first,
> then the AYN Thor. The riskiest changes come first. Each step names its ticket and the A/B switch that brings back
> the old behaviour. The ticket's Plane comment and the linked doc have the details. Part of the
> [Documentation Index](../INDEX.md).
>
> Checked against main at **9cce0f6** (waves 1-4). Where a ticket's list was written before a later change, the step
> follows the code and says « was: … ». Wave 5 was not on main yet: see the end of the page.

Titles: Fable 4D5300D1, Burnout 3 4541005B (PAL disc), Black 45410083, KOTOR 4C410003. Use only your own dumps.

How to report: per ticket, `plane comment XBA-<n>` with `step k: ok`, or `not ok` plus the log line. When something
regresses, rerun with the step's A/B switch and say whether it fixes it.

## Grep list (every run, Mac and Thor)

Keep each run's log (Mac: `2>&1 | tee run-<title>.log`; Thor: `adb logcat -s xboxrecomp`) and grep it for:

| Line | Ticket | Expected |
|---|---|---|
| `[STACK] ... resumes where no context is parked`, `parked ... resuming the closest` | XBA-101 | none |
| `[SEH] ... refused`, `[SEH] dispatch: chain broken` | XBA-101, XBA-112 | none |
| `[SEH] host fault on guest` | XBA-132 | Thor only: « raised to the guest's handlers » then normal play, or nothing |
| `[#DE]` | XBA-110, XBA-112 | none; otherwise note the address |
| `[KERNEL] STUB ordinal` | XBA-114, XBA-115 | none except 60 (IoBuildAsynchronousFsdRequest): say which title calls it |
| `[NET] nic probed (...), link down` | XBA-117 | once per run |
| `[APU-DSP]` | XBA-122 | send them (GP image hash, stalls) |
| `[SMC] N code page(s) of 16384 bytes write-protected` | XBA-118 | once, before « Starting game… » (4096 on the Thor) |
| `[SMC] code written at run time`, `code run outside the image` | XBA-118 | copy each one into the ticket |
| `[MEM] guest thread stacks: high-water mark` | XBA-104 | 8 or 16; no `STATUS_INSUFFICIENT_RESOURCES` |
| `[UNIMPL]`, `[HLT]`, `[DTR]` | XBA-111 | no `cli` / `sti`; send the rest |

### M2 · The risky changes, one run per title (about 1 h 30)

Default settings, nothing in the environment, then the grep list.

1. **Fable: generic stack switching and no memory profile** (XBA-101, XBA-103, XBA-104). The profile no longer sets
   a map size or `RECOMP_THREAD_STACKS`.
   - The loader's fibers run: `[STACK] context N: new guest stack`.
   - The first load finishes, with no hang at 0x00269210.
   - Title screen, AutoSave, then Oakvale. Play 10 minutes there: no crash, no hang.
   - The large reserves are lazy now (608 MB). Watch for an out-of-memory or `[CONTIG] arena exhausted` line.
   - A/B: `RECOMP_STACK_SWITCH=0` (Fable then hangs at the first load: expected), `RECOMP_LAZY_RESERVE=0`,
     `RECOMP_THREAD_STACKS=8`.
2. **All four: 16 kernel argument counts changed** (XBA-114). The changed ordinals are 60, 80, 163, 201, 208, 209,
   212-214, 216, 239, 241, 244, 248, 257 and 266, now 4 bytes per Xbox parameter.
   - Each title boots to its menus and in game as before. A crash or garbage right after one of those calls means a
     stack imbalance: send the last kernel lines.
   - Quit from the title's menu: it leaves as before (shutdown routines run first).
   - A/B: `RECOMP_THREAD_NOTIFY=0` (notify routines), `RECOMP_QUEUE_LIMIT=0` and `RECOMP_APC_WAKE=0` (XBA-133).
     There is no switch for the argument counts: report the title and the point where it broke.
3. **All four: the network link is now down** (XBA-117).
   - `[NET] nic probed (...), link down` appears once.
   - No multi-second stall after the logos compared with `RECOMP_NIC=0`. Time it both ways on one title.
   - Live or system-link menus (network.md check list) say there is no cable, and do not hang on « signing in ».
   - A/B: `RECOMP_NIC=0`; `RECOMP_NIC_TRACE=1` for the `[NIC]` lines.
4. **All four: new stereo downmix** (XBA-122; apu-dsp.md check list).
   - Play 2 min with `RECOMP_STATUS=s.json RECOMP_AUDIO_WAV=routed.wav`, then again with `RECOMP_APU_MIXDOWN=sum` into
     `sum.wav`.
   - Listen to both: dialogue in both ears, nothing louder or clipped, no sound lost compared with sum.wav.
   - Send the `apu_dsp` object, the `[APU-DSP]` lines and the gp_image hash of each title.
   - A/B: `RECOMP_APU_MIXDOWN=sum`.
5. **Burnout 3: PAL 60 is the default** (XBA-121).
   - Still 60 fps on the PAL disc.
   - With `RECOMP_PAL60=0`: 50 Hz (vblank log). With `RECOMP_GAME_REGION=na`: exactly the old behaviour.
   - (The 23:40 list said `RECOMP_PAL60=1` to get 60 Hz. PAL 60 became the default at 00:33.)
6. **Fable / all four: completion APCs are deferred** (XBA-102).
   - Loads and streaming as before.
   - (Was: « with no FABLE_INLINE_APC set ». That switch is gone.)
   - A/B: `RECOMP_INLINE_APC=1`.
7. **All four: a TIB per thread on titles without TLS** (XBA-113, XBA-112). The pads enumerate and respond (the USB
   controller thread now runs there). A/B: `RECOMP_TIB_PER_THREAD=0`.
8. **All four: code pages are write-protected** (XBA-118).
   - The `[SMC]` line appears.
   - With `RECOMP_SMC=0`: identical behaviour, and about the same load time for the first level.
9. **All four: SEH dispatch** (XBA-112).
   - No new `[SEH] dispatch: chain broken` lines.
   - A title that recovers through `__except` now goes on past that point.

## AYN Thor

### T1 · Switch the APK once (XBA-125; do this before anything else)

The full commands are in XBA-125 steps 1-10.

1. Create `xrecomp-release.p12` with keytool on the Mac. Keep it and its password in two encrypted places.
2. Put `XBA_RELEASE_KEYSTORE_B64` and `XBA_RELEASE_KEYSTORE_PASSWORD` into the Gitea secrets.
3. On the next main run, android-apk logs `signed with: release key` and your SHA-256.
4. On the Thor: back up `files` and `shared_prefs` with `run-as ... tar`, uninstall, install the new APK, restore.
5. From then on, install `xrecomp-latest` over it.

### T2 · Play the four titles (about 2 h; logcat throughout, grep list)

   - Fresh settings: `[GPUGL] GPU back end by default on this platform` and `Adreno (TM) 740 | OpenGL ES 3.2`. No
     « no GL context », « shader compile failed », « link failed » or « GL error ».

   - Renderer › Software: no `[GPUGL]` line.
   - A/B: Renderer › Software (`RECOMP_GPU=0`).
2. **Fable, stack switching on arm64** (XBA-101). Same as M2 step 1, into Oakvale.
3. **Host faults raised as guest exceptions** (XBA-132; Linux and Android only).
   - Look for the `[SEH] host fault on guest` lines.
   - If a title crashes on a guest address, the tombstone should show the original pc, not `seh_fault_tramp`.
   - A hang right after a « host fault » line is the known risk.
   - A/B: `RECOMP_SEH_FAULTS=0`.
4. **Pad hotplug and four ports** (XBA-123; app-shell.md « Device check (players and on-screen pad) »). Use a
   RECOMP_USB title with the Thor pad plus a Bluetooth pad.
   - The Bluetooth pad becomes pad 2.

   - Rumble goes to the right pad.
   - Pin port 1 to the Bluetooth pad.
   - A title that offers a memory unit finds none and still saves.
   - A/B: `RECOMP_USB_PADS=1` (the old single pad).
5. **The rest of M2 on arm64** (XBA-114, XBA-117, XBA-122, XBA-102, XBA-113): the four titles to their menus and in
   game. Pads respond. The `[SMC]` line says `of 4096 bytes` (XBA-118). Audio has no new crackle (XBA-122; compare
   the audio thread cost with and without `RECOMP_APU_REVERB=generic`).
6. **XBA-120 / XBA-134** Each title 2 min on GPU:

   - Fable in Oakvale with and without `RECOMP_GPU_MIPS=0` (expect less shimmer with mips).
   - `RECOMP_GPU_FFP=1` (off by default): same picture, « KB transformed on the CPU » near 0, fps both ways.
7. **XBA-107** Fable with `RECOMP_PACING=auto` and the profile's `RECOMP_GPU_FPS_CAP` removed from the pack's
   `env_default_android`, Frame cap Auto.
   - In Oakvale: `[GPU] pacing 30 fps ... adaptive`, and `[FBWIN] frame times` with a mean around 33.3 ms (note the
     sd; the goal is under 2 ms).
   - The 120 Hz panel line appears.
   - With Frame cap 30/60: `pacing auto off`.
8. **XBA-121** Settings › Graphics: Widescreen and 480p, Off by default. Turning them On writes the `recomp.cfg`

9. **XBA-131** app-shell.md « Device check (Controls, XBA-131) », 8 steps:
